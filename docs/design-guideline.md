# yorozu デザインガイドライン

yorozu 全体で共通のビジュアル規約。ツールが増えても一貫性を保つための基準です。

## デザインの正

デザインの正は、claude.ai の yorozu アーティファクト（https://claude.ai/artifact/6n1wTqy226vFk4937X44mP ）にある次の 7 ファイルとする。同じアーティファクトにある他のファイル（`-backup-*`、MV 案 `-mv-*`、`yorozu-v2`、`OGP-old` など）は検討の途中のもので、正ではない。

| 画面 | PC | SP |
|------|----|----|
| トップ（YZ10_100） | `yorozu-cyber-net`（1440px） | `yorozu-cyber-net-sp`（375px） |
| 画像変換（YZ20_100） | `yorozu-cyber-net-image`（1440px） | `yorozu-cyber-net-image-sp`（375px） |
| 動画変換（YZ30_100） | `yorozu-cyber-net-video`（1440px） | `yorozu-cyber-net-video-sp`（375px） |
| OGP | `OGP`（1200×630px） | — |

デザインと実装を食い違わせる場合は、その判断をこのガイドラインに書く（例: 下記の `letter-spacing` を入れない方針）。

- ナビの 1 項目めは、デザインでは「トップ」だが、実装では「ホーム」とする。英語版の「Home」とページ情報の名前（`PAGE_INFO`）にそろえるため。
- フッターの LINKS にある「REQUEST」は、デザインではトップのリクエスト欄（`#request`）を指すが、実装では GitHub の issue ページ（`https://github.com/InumberX/yorozu/issues`）を指す。トップのツール一覧の最後にある「次のツール」の行と、コンセプト欄の「こちら」も同じ issue ページを指す。
- 外部サイトへのリンク（`http://` / `https://` で始まるもの）は、すべて別タブで開く（`target="_blank" rel="noopener"`）。`PrimitiveButton` が既定で付ける。`noreferrer` は付けず、リンク先に参照元（Referer）を渡す。
- フッターのコピーライトは、デザインでは年（`© 2026 NiNE, …`）を入れているが、実装では年を入れない（`© NiNE, ALL RIGHTS RESERVED.`）。
- トップの見出しの 2 行目（縁取り文字）の線幅は、デザインでは PC 1.5px / SP 1px だが、実装では lg 以上 2px / lg 未満 1px とする。CSS の数値を整数にするため。
- トップのヒーローの下段（CTA と 3 つの数値）は、デザインには PC（1 行）と SP（縦に積む）しかない。実装では、sm 以上で数値を 3 列（CTA はその上）、md 以上で CTA と数値を 1 行に並べる。lg 未満の 3 列では、項目名の下に値を置く。
- トップのツール一覧は、デザインには PC（6 列の表）と SP（カード）しかない。実装では、md 以上で表にし（列幅は md で狭め、lg 以上でデザインの値）、md 未満のカードでは、sm 以上で OPEN / REQUEST を説明の最後の行の右端に置く。
- トップのツール一覧のツール名（と「次のツール」）は h3 にする。デザインでは見出しではない（`<b>`）が、SEC.01 の h2 の下の項目として見出しの階層に載せる。
- トップのヒーローの背景（デザインの `geo-twist-slow.svg`）は、SVG ファイルを置かず HTML と CSS で描く（`components/pages/YZ10_100/MainVisual`）。色をトークンから取り、動きを減らす設定の扱いをほかのアニメーションとそろえるため。線は拡大されず常に 1px になる。
- 中身の最大幅は、デザインでは 1240px（左右の余白 22px）だが、実装では `LayoutInner` の既定（1400px、左右の余白 32px）とする。ページ・フッターの左端を、すべて同じ `LayoutInner` の幅でそろえるため。
- 画像変換の手順のパネル（STEP 01〜03）は、デザインには PC（3 列）と SP（縦に積む）しかない。実装では、md 以上で「読み込む」を上の 1 行に置き、その下に「指定する」「変換する」を 2 列で並べ、lg 以上でデザインの 3 列にする。変換結果の行は、md 以上で表のように列をそろえ（列幅は md で狭め、lg 以上でデザインの値）、md 未満でデザインの SP の形にする。
- 画像変換の出力形式（WebP / AVIF）は、デザインでは `aria-pressed` のボタンだが、実装では見た目を同じにしたラジオボタン（`InputRadioCard`）にする。どちらか 1 つを選ぶ入力で、フォームの値として送るため。添え書き（「幅広く対応」など）は名前に含めず、説明として読ませる。
- 読み込んだファイルのサムネイルは、デザインでは画像のアイコンだが、実装では読み込んだ画像を出す（読み込むまではアイコン）。変換結果の行も、変換後の画像を出す。
- 押せない「変換する」ボタンは、デザインのとおり塗らずに枠と文字を沈ませる（`BaseButton` の contained が無効のとき）。
- 1 ファイルごとのエラー（形式・大きさ）は、デザインに指定がないため、そのファイルの行の枠をエラーの色にし、ファイル名の下に文言を出す。

## タイポグラフィ

| 用途 | フォント |
|------|---------|
| 和文・見出し | Zen Kaku Gothic New（400 / 500 / 700 / 900） |
| 英数字・ラベル・数値 | Share Tech Mono |

| 役割 | サイズ | 実装上の定義 |
|------|--------|-------------|
| h1 | 52px（下層ページは 32px） | `fontMaximumBold` / `fontHeading1` |
| 見出し | 20px | `fontHeading2` |
| 本文 | 13〜14px | `fontMedium` |
| 小さめの本文 | 12〜13px | `fontSmall` |
| キャプション | 12px | `fontCaption` |
| ラベル | 10〜12px（大きめ・数値は 12〜14px） | `fontLabel` / `fontLabelLarge` / `fontMono` |

いずれも `app/styles/variables/font.css.ts` に定義。ビューポート幅に応じて `clamp()` で最小値〜最大値の間を可変にしている（例: h1 は 32px 〜 52px）。

CSS に書く数値（px / rem などのサイズ指定）は整数にし、小数点は使わない。文字サイズも整数の px で指定する。`getFontSize` が出力する rem や、`clamp()` で可変にした結果の表示サイズが小数になるのは対象外（書く数値だけを整数にする）。既存の `sup` / `sub` の位置（`-0.5em` / `-0.25em`）と余白の `4.6vw` は例外として残している。

`letter-spacing` は当初 0.12〜0.24em を想定していたが、和文が混在すると読みにくくなるため**実装では入れない方針**とした。

## コンポーネント

- **パネル**（`components/ui/panels/BasePanel`）: 罫線 `rgba(92, 255, 177, 0.3)` の枠と、四隅の「＋」（`#C8FFE6`、11px）で囲んだ面。下地は `default`（背景色の 16%、グリッドを透かす）と `dense`（86%、メインビジュアル）。ページのセクションはこの中に置く。
- **角の飾り**（`styles/mixins/corner-mark.css.ts`）: パネルの「＋」（`cross`）と、塗りボタンの「┌」（`bracket`）を疑似要素 1 つで描く。列の区切りと罫線が交わる角にも `cross` を置く。
- **セクションの余白**: セクションどうしの間は、各セクションの下の余白だけで取る（トップは 40〜64px）。最後のセクションの下は `LayoutPageWrapper` の下の余白に任せる。
- **ボタン**（`components/ui/buttons/BaseButton`）: `contained` は主色で塗った四角に「┌」の飾り（ホバーで塗りと文字の色を入れ替える）、`outlined` は主色 60% の細い枠（ホバーで面を 12% 塗る）。大きさは `large`（高さ 48px）/ `medium`（40px）/ `small`（36px）。
- **フォーム**（`components/ui/forms/`）: Conform の `getInputProps` / `getCollectionProps` の戻り値と `errors` を受け取る。エラーと説明は `aria-describedby` で入力に結び付け、エラーの文言は `FormErrorMessage` で出す。zod の既定の文言は `ZodProvider` が画面の言語に置き換える（`common.json` の `validation`）。フォーカスはアンバー 2px の輪郭。
- **フォーカス表示**: `app/root.css.ts` の reset で、すべての要素の `:focus-visible` にアンバー（`border.accent`）2px・外側 3px の輪郭を付ける。輪郭の位置を変えたい部品（枠の内側に引く一覧の行など）だけ、各コンポーネントで上書きする。ページの先頭には、フォーカスが乗ったときだけ出る「本文へスキップ」のリンク（`components/common/SkipLink`）を置く。
